# writing-maestro 시안 공통 평가 기준 (v0, 도메인 무관)

대상: writing-maestro가 만든 시안(draft). 과제 도메인이 달라도(블로그, 가이드, 프롬프트, 스펙, README 등) 같은 잣대로 본다.
척도: 각 항목 1~5 (1=심각한 결함, 3=쓸 만하나 손봐야 함, 5=그대로 써도 됨). 근거 없는 점수는 쓰지 않는다. 항목마다 파일·위치·인용 한 줄을 댄다.

| # | 항목 | 무엇을 보나 |
|---|---|---|
| C1 | 과제 적합성 | brief.md의 요구(독자, 목적, 분량, 형식, 필수 포함 사항, 제외 사항)를 얼마나 지켰나. 빠진 요구와 요구하지 않은 것을 추가한 것을 센다. |
| C2 | 독자 판단·행동 지원 | 독자가 판단하거나 행동하는 데 필요한 정보를 골라 배치했나. 정보량이 많아도 밀도가 과하거나 독자에게 필요 없는 내용이 섞이면 감점. |
| C3 | 정확성·근거 | 수치, 이름, 링크, 코드/원본과의 일치. 근거 없는 단정, 링크 표기와 실제 주소 불일치, 원본(source/, 코드, 레지스트리)과 어긋나는 서술. 확인 가능한 것은 직접 대조한다. |
| C4 | 구조·탐색성 | 제목이 약속한 것과 본문이 맞나. 독자가 원하는 곳으로 바로 갈 수 있나(진입점, 순서, 목차, 항목 성격의 일관성). |
| C5 | 문장 품질 | 자연스러운 문장, 번역투·AI 티·군더더기·반복·기계적 연결의 정도. 한국어 문서면 높임말과 용어 일관성. |
| C6 | 구체성 | 독자의 실제 상황으로 내려왔나(예시, 실제 명령, 실제 값, 실제 실패 사례). 독자가 이미 아는 일반론에 머물면 낮게. |
| C7 | 사용 준비도 | 가장 적은 수정으로 바로 쓸 수 있나. 미완 placeholder, 모순, 깨진 서식, 사실 확인이 더 필요한 곳의 수를 센다. 필요한 수정이 무엇인지 목록으로 쓴다. |

## 시안별로 따로 적을 것 (점수 없음)
- 한 줄 요약: 이 시안이 다른 시안과 구별되는 점
- 가장 큰 결함 1개와 가장 큰 강점 1개 (근거 위치 포함)
- 사실 오류가 확인되면 목록 (위치, 글의 주장, 실제)

## 프로젝트(과제)별로 적을 것
- 시안 간 순위 (시안이 1개면 생략). 순위 근거는 C1~C7 점수와 연결한다.
- 조합 적합성: 조합에 쓰인 스킬들이 이 과제와 독자에게 맞았나. 시안 지시(NOTES.md, brief.md)와 결과물 사이에 어긋남이 있나.
- 시안 간 차별성: 같은 조합 안의 시안들이 실제로 다른 선택지였나, 문장만 다른 쌍둥이였나.
- writing-maestro 개선 후보: 이 과제에서 관찰된 문제가 스킬 지시(SKILL.md의 brief, 시안 지시, 조합 선택)나 레지스트리를 어떻게 고치면 줄어들지. 한 번의 관찰이면 "추정"이라고 표시한다.

## 평가자 규칙
- 읽기 전용이다. 시안 폴더와 레포의 어떤 파일도 고치지 않는다. 결과는 지정된 출력 파일에만 쓴다.
- 평가 대상은 시안 본문이다. NOTES.md는 시안 작성자의 자기 설명이므로 근거가 아니라 대조 대상이다.
- 사용자가 어느 시안을 골랐는지는 알려 주지 않는다. 폴더에 흔적이 있어도 점수에 반영하지 않는다(예: final/ 폴더는 선택 후 가공본일 수 있으니 시안과 구분해 따로 적는다).
- 원본이 접근 가능하면(코드, source/ 폴더, 링크 대상) 최소 3개의 사실 주장을 실제로 대조한다. 대조하지 못한 것은 "미확인"으로 적는다.
- 칭찬과 감점 모두 인용으로 뒷받침한다. 인상 평가("좋다", "자연스럽다")만 쓰지 않는다.
