4. A (28): C1 5로 요구 적합과 분량이 가장 좋지만 C2 3(접근 제어 단서 부족). 동점 처리: D가 비공개 요구의 핵심 구멍을 더 잘 막아 앞에 둔다.
순위는 합이 거의 같아 취향이 아니라 "C2와 비밀 안전"에 가중한 판단이다. 사용자가 분량 제약을 중시하면 A가 올라간다.

### 조합 적합성
- prompt-optimizer-copilot(A, B)과 write-agent-prompts(C, D) 모두 이 과제(에이전트에게 주는 한국어 프롬프트)에 맞았다. 전자는 짧고 절차가 분명한 지시서, 후자는 판단 단서가 풍부한 지시서를 낸다. 요구 2(비공개)처럼 "구조를 모르는 코드에 대한 설계 결정"은 후자(C, D)의 단서가 더 잘 맞았다.
- NOTES.md와 결과물의 어긋남: C의 NOTES는 "플랫폼 정책은 현재 문서로 확인"을 설계했다고 하고 본문에 있다(일치). D의 NOTES는 "키 노출 이력 확인 명령이 `-p`면 값이 출력되므로 고쳤다"고 하나, 같은 계열의 C 본문에는 `-p`가 남았다(계열 내 일관성 문제). A의 NOTES는 "스킬 1~9단계 수행"이라 하나 결과물에 비밀 비출력 규칙이 빠져 있다(자기 점검이 보안 항목을 못 잡음).
- 형식: brief는 "Claude Code에 붙여넣을 한국어 프롬프트 1개"다. A, B는 코드블록 하나로 붙여넣기 형태를 지켰고 C, D는 마크다운 제목과 내부 백틱이 있는 문서 형태로 나와 붙여넣기 경계가 불분명하다.

### 시안 간 차별성
- combo1 안(A vs B): 같은 스킬과 같은 흐름(조사 → 호스팅 → 구현 → 확인 → 검증 → 보고)에 문구와 상세만 다른 준쌍둥이다. 실질 차이는 B의 갱신 지연 경고·사전 로그인 도구 확인·`git push` 재배포, A의 noindex·서비스 워커 정책 명세 정도이고 선택지의 방향은 같다.
- combo3 안(C vs D): 의미 있게 다른 선택지다. C는 "수집·보관·제공 3역할" 틀과 후보 5개 함정, D는 "5역할 배치 표" 틀과 불변 조건·접근 제어 3계열·완료 체크리스트. 같은 지시로도 독립 실행 결과가 갈렸다(SKILL.md 19행의 의도와 일치).
