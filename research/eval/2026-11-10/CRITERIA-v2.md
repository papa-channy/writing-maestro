# writing-maestro 시안 공통 평가 기준 v2 (도메인 무관)

대상: writing-maestro가 만든 시안(draft). 과제 도메인이 달라도 같은 잣대로 본다.
척도: 각 항목 1~5 (1=심각한 결함, 3=쓸 만하나 손봐야 함, 5=그대로 써도 됨). 항목마다 파일·위치·인용 한 줄을 댄다. 근거 없는 점수는 쓰지 않는다.
v1 대비 바뀐 곳: 쌍대 비교의 질문을 "고치기 쉬운 결함과 다시 써야 하는 결함을 나눠 비교"로 바꿈. 항목은 v1과 같다.

| # | 항목 | 무엇을 보나 |
|---|---|---|
| C1 | 과제 적합성 | brief.md의 요구(독자, 목적, 분량, 형식, 필수 포함 사항, 제외 사항)를 얼마나 지켰나. 빠진 요구와 요구하지 않은 것을 추가한 것을 센다. |
| C2 | 독자 판단·행동 지원 | 독자가 판단하거나 행동하는 데 필요한 정보를 골라 배치했나. 정보량이 많아도 밀도가 과하거나 독자에게 필요 없는 내용이 섞이면 감점. |
| C3 | 정확성·검증 강도 | 수치, 이름, 링크, 원본과의 일치. 근거 없는 단정, 링크 표기와 실제 주소 불일치. 글이 주장한 검증 수준("대조해 확인", "측정함")이 실제로 한 일(서지·초록 확인인지 원문 대조인지, 인용 근거 파일이 존재하는지)과 맞는지도 본다. 확인 가능한 것은 직접 대조한다. |
| C4 | 구조·탐색성 | 제목이 약속한 것과 본문이 맞나. 독자가 원하는 곳으로 바로 갈 수 있나(진입점, 순서, 목차, 항목 성격의 일관성). |
| C5 | 문장 품질 | 자연스러운 문장, 번역투·AI 티·군더더기·반복·기계적 연결의 정도. 한국어 문서면 높임말과 용어 일관성. |
| C6 | 구체성·깊이 | 독자의 실제 상황으로 내려왔나(예시, 실제 명령, 실제 값, 실제 실패 사례). 독자가 이미 아는 조언을 넘는 판단 근거나 차별점이 있나. 근거를 많이 싣는 것과는 다르다(많이 실어 밀도가 과하면 C2에서 감점). |
| C7 | 사용 준비도 | 가장 적은 수정으로 바로 쓸 수 있나. 미완 placeholder, 모순, 깨진 서식, 사실 확인이 더 필요한 곳의 수를 센다. 필요한 수정을 목록으로 쓴다. |
| C8 | 독자 적합성 | brief의 독자 유형으로 모드를 정한다. **사람 독자**: 도입부가 이 글이 왜 필요한지(기존 글·기존 방식의 한계)를 납득시키나, 읽는 순서가 독자가 물을 순서와 맞나. **에이전트 독자**(프롬프트, 에이전트용 가이드·스펙): 완료 기준, 다음 행동, 오해 없는 지시, 막혔을 때 이어지는 경로가 있나. 어느 모드로 봤는지 점수표 아래에 한 줄로 적는다. |

## 시안별로 따로 적을 것 (점수 없음)
- 한 줄 요약: 이 시안이 다른 시안과 구별되는 점
- 가장 큰 결함 1개와 가장 큰 강점 1개 (근거 위치 포함)
- 사실 오류가 확인되면 목록 (위치, 글의 주장, 실제)

## 프로젝트(과제)별로 적을 것
- **쌍대 비교** (시안이 2개 이상일 때): 먼저 시안마다 결함을 둘로 나눠 적는다. **고치기 쉬운 결함**(링크 교체, 수치·표기 정정, 문장·항목 삭제, 미확인 문장 제거처럼 몇 분 안에 원문 구조를 건드리지 않고 고쳐지는 것)과 **다시 써야 하는 결함**(깊이 부족, 구성·독자 적합성 문제, 핵심 논지 부재처럼 구조를 바꿔야 풀리는 것). 가능한 모든 쌍에 대해 "고치기 쉬운 결함을 모두 고쳤다고 가정했을 때 독자에게 먼저 내밀 시안"을 하나 고르고 한 줄 이유를 쓴다. 동점은 허용하지 않는다. 그 결과로 순위를 만든다. 점수 합과 쌍대 순위가 다르면 그 이유를 쓴다. 분량 초과는 줄여서 풀리는지(고치기 쉬움) 내용 구성이 원인인지(다시 써야 함)를 판단해 적는다.
- 조합 적합성, 시안 간 차별성(쌍둥이인지), writing-maestro 개선 후보(한 번의 관찰이면 "추정"). v0와 같다.
- 시안이 1개면 점수표를 쓰지 않고 결함 목록(사실 오류, 누락된 제약, 내부 용어 노출, 필요한 수정)만 쓴다.

## 평가자 규칙
- 읽기 전용이다. 시안 폴더와 레포의 어떤 파일도 고치지 않는다. 결과는 지정된 출력 파일에만 쓴다.
- 평가 대상은 시안 본문이다. NOTES.md는 시안 작성자의 자기 설명이므로 근거가 아니라 대조 대상이다.
- 사용자가 어느 시안을 골랐는지, 이전에 다른 평가자가 어떻게 평가했는지는 알려 주지 않는다. 폴더에 흔적(final/, 가공본, 다른 평가 파일)이 있어도 보지 않고 점수에 반영하지 않는다. 특히 `scratchpad/eval/`은 열지 않는다.
- 원본이 접근 가능하면 최소 3개의 사실 주장을 실제로 대조한다. 대조하지 못한 것은 "미확인"으로 적는다.
- 칭찬과 감점 모두 인용으로 뒷받침한다. 인상 평가만 쓰지 않는다.
