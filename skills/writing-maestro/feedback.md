# 사용자 피드백

writing-maestro가 호출 때마다 읽는다. "사용자 기준"은 사용자가 직접 말한 것이므로 시안 지시의 품질 기준으로 넘긴다. 사이클 기록의 "스킬 관찰"은 시안 지시의 주의 사항과 레지스트리 수정의 근거다.
새 사이클에서 사용자가 시안을 평가하면 "사이클 기록" 아래에 한 절씩 더한다. 사용자가 말하지 않은 기준은 적지 않는다.

## 사용자 기준 (사용자가 직접 말한 것)
- 정보량보다 독자가 판단하는 데 필요한 정보를 골라 배치했는지를 본다. 근거가 많아도 글의 밀도가 과하면 감점("정보량이 많다고 좋은 글이 되는 것은 아니다").
- 발행 준비도를 본다: 가장 적은 수정으로 바로 낼 수 있는 원고를 높게 친다.
- 도입부가 기존 글의 한계를 짚어 이 글이 왜 필요한지 납득시키면 좋게 본다.
- 제목이 약속한 기준과 본문 항목의 성격이 일치해야 한다(선택 기준 목록에 사용법 항목이 섞이면 감점).
- 독자의 실제 상황으로 내려온 구체성(예: 한국어 업무 문서의 높임말·번역투 점검)을 좋게 본다. 독자가 이미 알 법한 조언에 머물면 낮게 본다.
- 출처 링크는 원문을 직접 가리켜야 하고, 링크 표기와 실제 주소가 맞아야 한다.

## 사이클 기록

### 2026-10-30 · 'AI 글쓰기 도구 고르는 법' 한국어 블로그 글, new · 직장인 · 2000자
평가는 사용자가 붙여 넣은 편집 평가(원고 기준, 인용 원문 대조는 하지 않음)다.

| 시안 | 평가 | 사용자 말 |
|---|---|---|
| 조합 2 시안 1 (blog-post-writing → general-writing) | 4위 | 간결하고 단계가 분명하지만 깊이가 부족하다. 짧은 글은 대화형, 긴 글은 문서 앱이라는 기준이 글 길이에만 기댄다 |
| 조합 2 시안 2 (같은 조합) | 1위, 선택 | 독자를 가장 잘 이해한 글. 도입부, 구성 순서, 한국어 업무 문서 점검이 좋다. 수정 문장 수만으로 효율을 재는 점, 가이드 원문 대신 기관 홈페이지 링크는 아쉽다 |
| 조합 3 시안 1 (investigating-sources → blog-post-writing → general-writing) | 2위 | 연구와 실용의 균형이 좋고 한계를 밝혀 신뢰도가 높다. 네 번째 기준이 선택 기준이 아니라 사용법이고, 'CNBC 보도' 표기가 NBC News 링크로 연결된다 |
| 조합 3 시안 2 (같은 조합) | 3위 | 근거가 가장 풍부하고 '문체가 남는가'라는 차별화된 관점이 있다. 논문을 많이 넣은 인상, 기계적인 문단 연결, 일반 독자에게 필요 없는 연구가 섞였다 |

스킬 관찰
- investigating-sources를 앞에 둔 조합: 근거 깊이는 높지만 조사한 연구를 많이 싣는 쪽으로 기울어 실용 가이드의 응집력이 떨어졌다. 블로그·실용 글에서는 "조사한 근거 중 독자 판단에 필요한 것만 고른다"는 선별 지시가 필요해 보인다.
- blog-post-writing → general-writing: 독자 행동 중심 구성과 자연스러운 한국어에서 가장 강했다. 근거를 넣지 않거나 하나만 넣어 깊이와 차별성은 약했다.
- 같은 조합의 두 시안은 품질 차이가 컸다(조합 2는 시안 2, 조합 3은 시안 1이 우세). 시안 하나로 조합의 우열을 판단하지 않는다.

### 2026-10-31 · design-maestro 종합 문서(목적·기능·파이프라인·사용법·레지스트리 추가법), docs · 레포 소유자와 레지스트리를 고칠 사람 · 한국어
| 시안 | 평가 | 사용자 말 |
|---|---|---|
| 조합 1 시안 1 (crafting-effective-readmes → technical-writing, 처음부터 위에서 아래로 읽는 순서) | 선택 안 됨 | 이유 언급 없음 |
| 조합 1 시안 2 (같은 조합, 상황별 진입점 표를 앞에 둔 참조 순서) | 선택 | "d2가 더 좋아" |

스킬 관찰
- 두 시안은 같은 조합이고 시안 방향 지시만 달랐다(읽는 순서형, 상황별 진입점형). 사용자는 진입점형을 골랐고 이유는 말하지 않았다. 이 한 번으로 조합이나 문서 구조의 우열을 일반화하지 않는다.

### 2026-11-07 · 'CEO 다시 시작' 게임 프로토타입 디벨롭 논의용 문서 세트(현 게임 분석·결정 사항·게임 구조·데이터 스키마·색인), new · 프로젝트 오너와 이후 AI 채팅 세션 · 한국어
| 시안 | 평가 | 사용자 말 |
|---|---|---|
| 조합 2 시안 1 (build-evidence-map → writing-design-docs) | 선택 안 됨 | 이유 언급 없음 |
| 조합 2 시안 2 (같은 조합) | 선택 안 됨 | 이유 언급 없음 |
| 조합 3 시안 1 (writing-design-docs → writing-for-agents) | 선택 안 됨 | 이유 언급 없음 |
| 조합 3 시안 2 (같은 조합) | 선택 | "최종 선정: combo3-d2만 남기자" |

스킬 관찰
- 네 시안 모두 오케스트레이터의 분석 노트에 있던 수치 오류를 코드 대조로 바로잡았다(해외 가중치 합, A/B 테스트 횟수, 보상 광고 금액). 분석 노트를 입력으로 줄 때 "코드가 우선"이라는 지시가 유효했다.
- build-evidence-map을 앞에 둔 조합: 증거 지도(.doubt.json)와 헤드리스 측정이 붙어 근거는 가장 두터웠지만 선택되지 않았다. 이유는 말하지 않아 일반화하지 않는다.
- writing-design-docs → writing-for-agents: 이후 AI 세션이 따를 논의 절차(단계별 완료 기준, 컨텍스트 포인터)를 얹은 쪽이 선택됐다. 독자가 AI 세션일 때 이 조합이 맞는 방향일 수 있으나 한 번의 선택이라 단정하지 않는다.
- 생성 중 네트워크 오류로 네 서브에이전트가 모두 끊겼고, 부분 산출물을 확인한 뒤 SendMessage로 남은 작업을 지정해 재개하니 전부 완료됐다. "실패한 시안은 다시 돌리지 않는다" 규칙은 새로 돌리는 경우이고, 같은 에이전트 재개는 가능했다.

### 2026-11-10 · 시안 25개 에이전트 공통 평가 취합 (사용자 평가 아님, 각 항목 1~2회 관찰)
스킬 관찰
- 본문이 "원문과 대조해 확인했다"고 쓴 곳이 실제로는 서지·초록 수준이었거나, 레포에 없는 파일을 근거로 인용한 사례가 있었다(블로그, youtube). 근거 조사·검수 스킬이 든 조합의 지시에는 "확인했다는 문장은 이번에 연 원본에 한하고 못 한 것은 미확인으로 쓴다"를 넣는다.
- 분량이 brief의 수치를 넘기 쉽다(youtube 10~17KB에 23~26KB, CEO 세트 180KB). brief 분량이 "안팎·필요한 만큼"이면 시안 지시에 실측 상한을 붙인다.
- write-agent-prompts: 기존 코드에 끼워 넣을 모듈의 킥오프에서 통합 제약(교체 대상 함수, 호환할 타입)이 빠졌다(C.S.I-mcp). brief에 제약 목록이 있으면 시안이 반영 여부를 NOTES 대조표로 적게 한다.
- build-evidence-map, docs-sync-audit: 작업 복사본·상태 파일이 시안 폴더 최상위에 섞였다(`_work/`, `audit/`, `.drift.json`). 본문 파일 목록을 NOTES 맨 위에 둔다.
